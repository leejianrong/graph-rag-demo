# kggen dataset

A synthetic knowledge graph with questions and documents derived from it, generated by kggen (seed 0, 1,000 entities). Everything here comes from the world model; none of it is the output of any pipeline.

## Files

| File | What it is |
|------|------------|
| `world.json` | The ground truth: `entities` (id, name, type, community, aliases, distractor) and `edges`, the facts (id, subject, predicate, object, valid_from, valid_to). `valid_to` is null while a fact still holds. |
| `questions.json` | Questions: `question`, `type` (entity, set, count, compare, superlative, unanswerable, false_premise, as_of, latest, retracted, path), `hops`, `answer` (an entity id; empty for a set or count), `answers` (every correct entity id), `number` (a count's answer), `accepted_answers` (names and aliases), `supporting_facts` (fact ids in hop order: the first gold path) and `gold_paths` (one fact chain per correct answer), `answer_kind` and `grading` (how to score it), and for the declining types `abstain` and (for a false premise) `premise` with the contradicting fact and the correction. Temporal types (as_of, latest, retracted) add `as_of` (a year) and `stale_values` (names that held at another time and are wrong now). |
| `documents.json` | Template documents. Each has `sentences`; each sentence names the `fact_ids` it expresses and its entity `mentions` (character offsets into the document `text`). |
| `world.stats.json` | What the world realised against each knob in the spec. |
| `spec.json, questions_spec.json, render_spec.json` | The three specs that made this dataset. |

## Make it again

The same specs give the same bytes:

```
kggen export --spec spec.json --questions-spec questions_spec.json --render-spec render_spec.json --out dataset.zip
```
